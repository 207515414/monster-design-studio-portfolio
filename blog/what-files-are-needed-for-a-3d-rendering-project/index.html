Insights / Project files

What files are needed for a 3D rendering project?

The best starting package combines the current design record with a clear view list and named decisions. Not every project begins complete, but gaps should be visible before scope and timing are confirmed.

Drawings that establish the space

Send current plans, elevations and sections with dimensions and revision identifiers. For exterior work, include site or context information where available. For interiors, reflected ceiling plans, joinery elevations and furniture layouts may answer questions that a floor plan alone cannot.

Model files and exchange formats

Share the available model and identify the software or export format. Note whether it is a design model, a coordination model or an earlier massing study. A model can accelerate setup, but it does not replace confirmation of materials, visible details or the governing drawing revision.

Materials, furniture and visual direction

Provide finish schedules, material boards, product references and any confirmed FF&E selections. Reference images can explain lighting or atmosphere, but label them as mood references so they are not mistaken for project-specific requirements.

View and delivery requirements

Mark camera positions on the plan or describe the spaces each image must explain. Include output dimensions, intended use, orientation, target date and review milestones. If cameras are still open, make camera development part of the agreed scope.

What to do when information is missing

Create a short gap list. For each item, decide whether the team will supply it, whether a stated placeholder may be used or whether production should wait. This prevents hidden assumptions from appearing late in review. The broader brief guide helps connect these files to audience and feedback responsibilities.

Before sending: confirm revisions, remove superseded files, name one review owner and include a view-by-view requirement list.
