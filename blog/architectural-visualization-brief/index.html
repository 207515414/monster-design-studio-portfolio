What to include in an architectural visualization brief.

A clear brief connects the image package to a project decision. It records what is fixed, what is still open and who can approve feedback.

1. Explain the project stage and audience

State whether the images support an internal design review, a competition, a client presentation, a planning discussion or marketing preparation. Describe who will review them and what that audience needs to understand. This context influences view selection and the appropriate level of finish.

2. List the required views and outputs

Name each interior or exterior view, its intended use, orientation and output size. Mark priority views separately from optional views. If the camera is not confirmed, provide annotated plans or reference angles so camera development can be included explicitly in the scope.

3. Identify the current source files

List plans, elevations, sections, model files, site images, landscape information, material boards and furniture references. Add dates or revision codes so everyone knows which version governs production. Our file checklist provides a more detailed handoff.

4. Separate decisions from references

Mark elements that must be represented accurately, design items still under review and mood references that communicate atmosphere only. A reference image should not silently override the project drawings. Where information is missing, agree whether a placeholder, a stated assumption or a delayed start is appropriate.

5. Define feedback and timing

Name one person responsible for consolidated comments, the review milestones and the target delivery date. Record which changes are included in the confirmed scope and how design changes will be handled. This makes both schedule and quotation easier to evaluate.

Minimum briefing set: project stage, audience, current drawings, model status, view list, material direction, output size, deadline and one review owner.
